# BiasLens Public Visual Refresh and Proof Assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refresh every public BiasLens page into a darker BeAccessible-aligned visual system and publish a fictional recruitment case study plus a sample Algorithm Defence File as both public web pages and downloadable branded PDFs.

**Architecture:** Keep the authenticated BiasLens application untouched. Extend the existing public Next.js layer with shared public components, canonical proof-content modules, two new public proof routes, and two server-side PDF download routes generated with the already-installed `pdf-lib` package. The web pages and PDFs must consume the same canonical proof content so factual and claims wording cannot drift between formats.

**Tech Stack:** Next.js 16.2.9 App Router, React 19.0.0, TypeScript 5.5.4, Vitest 2.1.8, `pdf-lib` 1.17.1, existing BeAccessible CSS design tokens, Vercel, existing Supabase middleware.

## Global Constraints

- Public visual direction: full BeAccessible-aligned system, not a superficial dark mode and not a near-copy of the BeAccessible homepage.
- Dominant palette: Deep Blue `#1F3F6B`, Mid Blue `#2F5C9A`, Soft Blue `#4A78B5`, White `#FFFFFF`.
- Reduce white/light canvas dominance; use dark/tinted sections, subtle structural grid treatment and restrained high-clarity white surfaces.
- BiasLens remains a BeAccessible product and retains its own product identity.
- Existing authenticated dashboard, assessment engine and protected application routes are out of scope.
- Existing enquiry submission, Airtable persistence and Resend notification behaviour must not change.
- All fictional material must be visibly labelled fictional.
- BiasLens identifies evidence and signals requiring investigation; it does not prove discrimination.
- BiasLens does not replace legal advice, formal legal classification or conformity assessment.
- BiasLens assesses systems, processes and aggregated outcomes, not individual people.
- Fairness signals must not be presented as causation or unlawful discrimination.
- Sample-size guardrails are product methodology, not statutory thresholds or legal safe harbours.
- Accessibility demonstration is distinct from accessibility testing, validation and conformance.
- Preserve semantic landmarks, keyboard operation, visible focus, reflow, reduced-motion safety, clear form errors and `Listen to this page`.
- Do not claim the generated PDFs are PDF/UA or WCAG conformant unless separately validated.
